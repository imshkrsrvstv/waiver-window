# Visual direction

Waiver Window is an industrial approval desk for a bounded manufacturing exception. The central object is a permit with exact scope, next to the job being evaluated. The signature visual is a finite allocation ruler: existing reservations occupy tangible amber segments and the proposed job appears as a marked preview. It always labels quantities as app allocations, never physical stock or shipment clearance.

Two arrangements were considered: a dense ledger with a side inspector, and a split permit/job desk with the ledger below. The second leads with the actual decision, while the reservation history remains one click away. A compact top navigation offers Coverage and Allocation history; the visible waiver selector scopes both views. No repeated metric-card grid.

Palette: porcelain #f2f4ef, ink #243633, oxidized copper #336f65, brass #91622d, deep evergreen #172a27. Paper-like surfaces and restrained inset edges organize the desk without ornamental machinery. The native system sans stack keeps forms legible inside Jira; the large allowance values and generous title rhythm provide identity without ornamental lettering. Light/dark use full token sets, with explicit system-first persisted choice and reduced motion.

The form/dialog vocabulary stays familiar. Positive coverage, uncertainty, mismatch and revoked state each have distinct text and icons as well as color. Every approval/quantity action shows the consequence and returns a checkable receipt. Source links and provenance remain adjacent to the condition they support.

## Interaction hierarchy

The ruler describes this app's finite allowance; it does not imply that physical stock has moved. Solid brass marks represent existing allocations. The hatched proposed segment makes the next quantity visible without recording it. The remaining figure and legend state the same quantities in text, so the graphic is not the only way to understand the decision.

The left document preserves the exact approved scope. The right work area selects one job, checks it and asks for an explicit allocation. On narrow screens the job task moves ahead of the supporting permit, while the scope remains fully available. History is a deliberate second view rather than an assortment of dashboard metrics.

Provenance is collapsed by default. Full, copyable permit and selected-job identifiers support the read-only MCP workflow without dominating the ordinary decision. If clipboard access is unavailable, the field selects its text and explains manual copying instead of falsely reporting success.

## Complete themes and accessibility

The first paint uses system preference unless the person has selected a theme before. A synchronous same-origin theme bootstrap avoids an incorrect initial flash without inline script permission. Both token sets cover forms, native dialogs, tables, status conditions and error states. Theme switching disables color transitions briefly so intermediate colors do not undermine readability.

Controls have visible keyboard focus; dialogs have explicit headings, Escape behavior and focus return. Coverage reasons are native disclosures. Color is always paired with a label or symbol. The page uses native scrolling and reduced-motion behavior, with no decorative background competing with the task. Desktop, 390-pixel and 320-pixel layouts were inspected; automated checks are recorded in TESTING.md.

## Demonstration art direction

The film extends the same measured document language: porcelain opening, ink statements, copper alignment marks and one finite brass ruler. Avoid generic particle backgrounds, neon gradients or floating fake dashboards. Editorial graphics explain the quantity conflict; real captured screens prove the workflow.

Use a constant 16:9 output with a stable application frame. Camera movement should approach a condition or quantity before the action, hold the consequence, then return. The frame never changes size. A licensed local IBM Plex Sans face is suitable for the film's editorial graphics; app footage retains its native system typography. The product name and final verified address carry the closing, without decorative third-party logos.
